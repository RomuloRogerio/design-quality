# design-quality

AI가 생성한 인터페이스를 평가하고 수정하는 Claude Code 스킬입니다.

AI는 UI를 빠르게 생성합니다. 하지만 항상 같은 방식으로 틀립니다. 보라-파랑 그라데이션, 그라데이션 텍스트, 빛나는 테두리, 아이콘 대신 이모지, 내용 없는 카드 그리드, Inter만 쓰는 타이포그래피, 업무 도구에 과도한 히어로 제목. 이것들이 특징입니다. 이 스킬은 이를 체계적으로 감지하고, 8개 차원에서 인터페이스를 채점하며, 단계별로 수정합니다.

---

## 기능

**리뷰 모드** — UI의 AI 조잡 특징을 감사하고, 8개 차원(1–10점)으로 채점하며, 우선순위 수정 목록(P0–P3)을 생성합니다.

**생성 모드** — UI를 작성하기 전에 제품 방향성을 먼저 확립합니다. 방향성 없이는 시작을 거부합니다. 트렌드가 아닌 제품이 실제로 하는 일에서 캐릭터, 세계관, 순간, 시그니처 디테일을 도출합니다.

**수정 모드** — 10단계 순차 패스로 수정을 적용합니다: 간격 → 색상 → 아이콘 → 카피 → 타이포그래피 → 레이아웃 → 디테일 → 접근성 → 비주얼 → 모션.

**다듬기 모드** — 전반적으로 잘 설계됐지만 미묘하게 어색한 인터페이스용. DevTools에서 10% 속도로 늦춰 모든 상태를 확인합니다.

React, Tailwind, HTML/CSS, Vue, Svelte, 대시보드, 앱, 랜딩 페이지, 컴포넌트에서 작동합니다.

## 해결하는 문제

### AI UI의 모습

LLM이 제약 없이 UI를 생성할 때, 매번 같은 인터페이스를 만듭니다. 수천 개의 Dribbble 스크린샷, 포트폴리오, SaaS 랜딩 페이지를 학습했고, "실제로 유용한"보다 "첫눈에 인상적인"에 최적화됩니다.

결과는 항상 알아볼 수 있습니다:

**색상:** 보라-파랑 그라데이션 배경. `background-clip: text`를 쓴 그라데이션 텍스트. 채도 높은 빛나는 테두리. 콘텐츠 뒤의 방사형 색상 블럽.

**타이포그래피:** 업무 도구에 과도한 히어로 제목. 모든 섹션에 트래킹이 적용된 대문자 레이블. 레이블에 이모지 혼합("🚀 시작", "신기능 ✨"). 다른 타이포그래피 결정 없이 Inter 또는 Roboto만.

**레이아웃:** 콘텐츠 채우기용 3열 카드 그리드. 모든 것 중앙 정렬. 제품 이유 없이 적용된 다크 테마. 모든 섹션 같은 간격.

**카피:** "지금 바로 워크플로우를 혁신하세요." "강력한 통합." "고급 분석." 카테고리 어떤 제품에도 맞을 카피.

**정체성:** 제품명을 어느 경쟁사로 바꿔도 인터페이스가 맞습니다. 세계관도, 시그니처도, 순간도 없습니다 — 오직 이 제품만이 가질 수 있는 것이 없습니다.

### 이 스킬이 다른 점

이러한 패턴을 체계적으로 감지하고, 있는 것을 채점하며, 올바른 순서로 수정합니다. 또한 UI를 작성하기 전에 제품 방향성을 요구함으로써 처음부터 예방합니다.

## 모드

### 리뷰 모드

입력: 스크린샷, HTML/CSS 소스, 프로젝트 폴더, URL, 또는 아티팩트 링크.

출력:
```
## AI 조잡 감사
[각 발견 사항, 위치 및 심각도 포함]

## 템플릿 확인
[이것이 카테고리의 어떤 제품에도 맞는가?]

## 스코어카드
제품 적합성:  X/10   [한 줄 메모]
계층 구조:    X/10
명확성:       X/10
취향:         X/10
절제:         X/10
밀도:         X/10
크래프트:     X/10
반응형:       X/10
종합:         X/10

## 평결
가장 좋은 점:
가장 나쁜 점:
필수 수정(P0): [있다면]
빠른 개선(P1): [상위 3개]
```

심각도 기준:
- **P0** — 사용성 또는 가독성을 해침. 다른 무엇보다 먼저 수정.
- **P1** — 명확히 AI 생성물처럼 보임.
- **P2** — 크래프트를 약화시키지만 망가뜨리지 않음.
- **P3** — 있으면 좋은 개선.

### 생성 모드

UI를 작성하기 전에 스킬이 요구하는 것:
1. **컨텍스트 유형** — 앱 화면(밀도가 지배) vs. 페이지(구성이 지배)
2. **제품 이해** — 무엇을 하는지, 누구를 위한 것인지, 핵심 작업이 무엇인지
3. **방향성** — 제품에서 도출된 5가지 축: 제품, 캐릭터, 세계관, 순간, 시그니처
4. **디자인 다이얼** — 빠른 신호로서의 세 가지 조절기: 변화도 / 모션 / 밀도(각 1–10)

확인 후, 세션 간 방향성을 유지하는 `PROJECT_DESIGN.md` 파일을 프로젝트 루트에 생성합니다. 이후 세션은 이 파일을 먼저 읽습니다 — 방향성이 표류하지 않습니다.

시간 추적 도구를 위한 방향성 예시:
```
제품: 시간 추적을 싫어하는 프리랜서를 위한 시간 추적 도구.
캐릭터: 차분한, 정확한, 약간 따뜻한
세계관: 시계, 타이머, 조용한 집중 세션
순간: 시간이 쌓이는 주간 뷰; 청구서 생성 순간
시그니처: 활성 타이머의 미묘한 초침 애니메이션
```

### 수정 모드

10개 순차 패스 — 다음을 시작하기 전에 각각을 완료:

1. **간격** — 8px 그리드 정렬, 리듬, 그룹화
2. **색상** — 조잡한 요소 제거, 중성 색조에서 구축
3. **아이콘** — 하나의 라이브러리, 하나의 크기, 하나의 스트로크 굵기, `currentColor`
4. **카피** — 이모지 레이블 제거, 소리 지름 진정, 제품 고유 카피 작성
5. **타이포그래피** — 계층 구조, 굵기, 제목에 `text-wrap: balance`
6. **레이아웃** — 정렬, 밀도
7. **디테일** — 동심원 반경, 그림자(그림자와 테두리 동시 사용 금지), 테두리
8. **접근성 및 터치** — 포커스 상태, `aria-label`, `touch-action: manipulation`, 44px 타겟
9. **비주얼** — 빈 상태 일러스트, 아이콘 일관성, 이미지 종횡비
10. **모션** — 마지막 패스, 의미가 추가되는 곳에만

### 다듬기 모드

전반적으로 잘 설계됐지만 미묘하게 어색한 인터페이스용.

기법: DevTools(애니메이션 패널)에서 인터페이스를 10% 속도로 늦춥니다. 모든 상태를 확인합니다: hover, focus, active, loading, empty. 10%에서 어색하게 느껴지는 것이 전체 속도에서 잘못된 것입니다.

## 스코어카드 차원

| 차원 | 질문 |
|---|---|
| **제품 적합성** | 시각적 방향이 제품의 실제 역할과 대상에 맞는가? |
| **계층 구조** | 사용자가 첫 번째, 두 번째, 세 번째로 중요한 것을 볼 수 있는가? |
| **명확성** | 레이블, 액션, 데이터, 상태를 이해하기 쉬운가? |
| **취향** | 템플릿처럼 보이지 않으면서 의도적으로 느껴지는가? |
| **절제** | 불필요한 장식, 채우기, 스타일 코스플레이가 없는가? |
| **밀도** | 정보량이 작업에 적합한가? |
| **크래프트** | 간격, 타이포그래피, 정렬, 대비, 컴포넌트 상태 — 정제됐는가? |
| **반응형** | 디자인이 모바일과 좁은 레이아웃에서 작동하는가? |

## 방향성 프레임워크

코드를 작성하기 전에 모든 디자인에 필요한 5가지 축:

**제품** — 무엇을 하는지, 누구를 위한 것인지, 한 문장으로.

**캐릭터** — 2–3개의 구체적인 단어. `차분한, 정확한, 약간 따뜻한` 또는 `빠른, 기술적인, 재미있는`.
금지어: 깔끔한, 모던한, 세련된, 미니멀한, 프리미엄한. 이 단어들은 모든 템플릿에 해당됩니다.

**세계관** — 제품이 자연스럽게 속하는 재료나 장소.
- 메모 앱 → 종이와 잉크
- 모니터링 도구 → 계기판과 야간 근무
- 여행 앱 → 지도와 창문 빛
- 금융 도구 → 원장, 깔끔한 열, 조용한 권위

이것이 중성 색상, 강조색, 시각적 순간에 색조를 더합니다.

**순간** — 디자인이 풍부하고 구체적이 되는 화면의 1–2곳.
다른 모든 것은 조용하게 유지해서 이것들이 즉시 읽히게 합니다.

**시그니처** — 오직 이 제품만이 가질 작은 디테일 하나, 일관되게 반복.
- 모니터링 도구 → 실시간 상태 점
- 개발자 도구 → 키캡 미학
- 배달 앱 → 경로 라인

디테일 하나, 다섯 개가 아닌.

### 디자인 다이얼

각 방향성 제안에 표시되는 세 가지 조절기:

```
변화도  ░░░░░░░░░░  1–10   (1 = 중앙/미니멀, 10 = 대담/비대칭)
모션    ░░░░░░░░░░  1–10   (1 = 정적, 10 = 애니메이션 풍부)
밀도    ░░░░░░░░░░  1–10   (1 = 여유/에디토리얼, 10 = 대시보드/고밀도)
```

---

## 적용되는 디자인 원칙

### 간격
- 8px 그리드. 모든 마진, 패딩, 갭은 4 또는 8의 배수.
- `mt-[13px]`는 항상 잘못됨. 수정하세요.
- 공간은 그룹화를 보여줌: 내부 갭 < 외부 갭.

### 색상
- 하나의 중성 색조 램프, 세계관 방향으로 기울임.
- 하나의 강조색, 드물게 사용: 주 액션, 선택, 중요한 하나의 숫자.
- 세 가지 텍스트 역할: 주, 부, 희미. 미묘하게 다른 열 가지 회색 불필요.
- 새 색상 토큰에는 OKLCH 선호: `oklch(L% C H)` — 지각적으로 균일하고 조정이 쉬움.
- 금지: 표면의 색상 그라데이션, 그라데이션 텍스트, 컬러 발광, 방사형 블럽, 네온 테두리.

### 타이포그래피
- 독특한 디스플레이 폰트와 깔끔한 본문 폰트 페어링. 굵기 대비 최대화.
- 모든 제목에 `text-wrap: balance`. 본문 텍스트에 `text-wrap: pretty`.
- `:root`에 `-webkit-font-smoothing: antialiased` (macOS에서 더 선명하게 렌더링).
- 본문 텍스트 최소 14px(16px 권장). 페이지당 h1 하나.

### 컴포넌트
- 버튼: 동사 우선 레이블. 섹션당 하나의 주요 버튼.
- 아이콘에 이모지 사용 금지. 하나의 아이콘 라이브러리, 하나의 스트로크 굵기, `currentColor`만.
- 카드: 그림자 또는 테두리, 둘 다는 안 됨.
- 빈 상태: 일러스트 + 제목 + CTA. 그냥 비어있으면 안 됨.
- 로딩: 300ms 지연 후 스켈레톤 화면(스피너 아님).

### 하나의 밝은 요소 규칙
각 화면에는 하나의 정제되고 풍부한 요소만. 나머지는 모두 조용하게.
내비게이션, 버튼, 배경 같은 크롬은 콘텐츠와 경쟁하지 않습니다.

## 다듬기 체크리스트

UI를 완료로 표시하기 전에:

- [ ] 아이콘에 이모지 없음(SVG 사용: Heroicons / Lucide / Phosphor / Radix)
- [ ] 모든 클릭 가능 요소에 `cursor-pointer`
- [ ] 텍스트 대비 ≥ 4.5:1(WCAG AA)
- [ ] 키보드 탐색용 포커스 상태 가시(`focus-visible`, `outline` 제거 금지)
- [ ] 모든 아이콘 버튼에 `aria-label`
- [ ] 모든 폼 입력에 연관된 `<label>`
- [ ] `prefers-reduced-motion` 준수
- [ ] 버튼에 `touch-action: manipulation`
- [ ] hover 상태에 `@media (hover: hover) and (pointer: fine)` 사용
- [ ] 텍스트, 칩, 배지가 좁은 너비에서 잘리지 않고 줄바꿈
- [ ] 375px, 768px, 1024px, 1440px에서 반응형
- [ ] 리뷰 모드에서 P0 발견 없음
- [ ] 빈, 로딩, 오류 상태 모두 처리
- [ ] 동적 숫자에 `font-variant-numeric: tabular-nums`
- [ ] 제목에 `text-wrap: balance`
- [ ] 어디에도 `transition: all` 없음

## 감정 상태 확인

리뷰 모드 중 스킬이 실행하는 확인. 각 핵심 상태에서 사용자가 느끼는 것을 묻고, 인터페이스가 그 감정을 인식하는지 확인합니다.

로딩: 불안한가? 기다리는가?
빈 상태: 길을 잃었나? 처음인가?
오류: 당황스러운가?

다음 경우 플래그:
- 로딩 카피가 "로딩 중..."만 → P2("데이터를 가져오는 중"이어야 함)
- 시스템 오류에 사용자를 탓하는 오류 메시지 → P1
- 빈 상태가 아무것도 제공하지 않음 — 설명도 CTA도 없음 → P1
- 성공이 조용히 흡수됨(확인 없음) → P2

## 피크-엔드 법칙

다단계 플로우의 경우, 스킬은 플로우가 기억되는 방식을 지배하는 두 순간을 매핑합니다:

- **피크**: 가장 감정적으로 강렬한 순간(주문 완료, 폼 제출, 첫 결과). 잘 설계됐는가?
- **엔드**: 최종 화면/상태. 명확하게 확인하고 따뜻하게 마무리되는가?

관리용 화면, 혼란스러운 상태 페이지, 해결되지 않은 오류로 끝남 → P1.

## 마이크로 폴리시 값

### 동심원 보더 반경

외부 요소 반경 = 내부 요소 반경 + 사이의 패딩.

```css
/* 잘못됨 */
.card { border-radius: 12px; padding: 16px; }
.card-inner { border-radius: 12px; } /* 너무 작음 — 내부 모서리가 날카로움 */

/* 올바름 */
.card { border-radius: 24px; padding: 12px; }
.card-inner { border-radius: 12px; } /* 24 - 12 = 12 ✓ */
```

### 누름 애니메이션

```css
button {
  transition: transform 150ms ease-out;
}
button:active {
  transform: scale(0.96);
}
```

항상 0.96 — 0.95보다 작으면 안 됨.

### 트랜지션

```css
/* 절대 사용 금지 */
transition: all 200ms ease;

/* 항상 구체적으로 */
transition: transform 200ms ease-out, opacity 200ms ease-out;
```

### 터치 타겟

```css
.icon-button {
  width: 20px;
  height: 20px;
  position: relative;
}
.icon-button::before {
  content: '';
  position: absolute;
  inset: -12px; /* 레이아웃 변경 없이 히트 영역을 44×44로 확장 */
}
```

## 모션 원칙

모션은 예산입니다. 모든 애니메이션에 물어보세요: 제거하면 인터페이스가 더 나빠지나요, 아니면 단지 덜 화려해지나요? 답이 "덜 화려해진다"면 제거하세요.

**고빈도 인터랙션(하루 >10회 사용): 커스텀 애니메이션 없음.**
행 hover, 키스트로크 피드백, 탭 전환, 토글 — 즉각 반응, 또는 ≤150ms 최소 트랜지션.

**저빈도 액션(드물거나 처음 사용): 애니메이션을 가치 있게 만들기.**
온보딩 단계, 빈 상태 → 첫 항목, 성공 상태 — 단순 ease-out으로 150–300ms.

**인터랙티브 요소에는 keyframe보다 CSS transition 사용.**
transition은 중단 가능합니다. 사용자가 드로어를 열고 애니메이션 중에 닫으면, transition은 부드럽게 반전됩니다. keyframe 애니메이션은 처음부터 다시 시작합니다.
